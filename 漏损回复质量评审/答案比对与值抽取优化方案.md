## 1. 问题陈述

### 1.1 现象

智能体的回答里，**绝大部分数值是对的**，但评测结论判为 `PARTIAL` / `UNQUALIFIED`，或者干脆 `UNEVALUABLE`。七维诊断（期间、范围、粒度、字段、行覆盖、数值、单位口径）虽然细分了问题类型，但**没有解决误判本身**——因为维度的来源同样是易错的抽取与判断。

### 1.2 一句话根因

> 当前比对链路默认「智能体的回答是一张结构规整、行列齐全、精度统一的表格」，而实际回答是自由文本。

链路上的每一环都在为这个假设付出代价：解析不出表就整题交 LLM、多一行就降级、四舍五入就判错值、答案先输出一张过程表则结果表被直接裁掉。

### 1.3 目标与非目标

**目标**

| 编号 | 目标 | 验收 |
|---|---|---|
| G1 | 结构化抽取覆盖至少 95% 的历史回答 | 对校准集统计 `extract_coverage` |
| G2 | 把「数据对但判错」的误判率降到 5% 以下 | 校准集人工比对 |
| G3 | 「没抽到」与「算错了」在结论上彻底分开 | `ABSENT` 独立状态，不进入错误统计 |
| G4 | 每个判定都能指回答案原文片段 | 比对明细含 `span` 与 `trace` 定位 |

**非目标**

- 不改变 SQL 基准的生成方式（黄金值来源不动）。
- 不降低评测严格度。改造后错值仍然判错，只是不再把「表达差异」和「格式差异」当成错。
- 本期不做多轮对话上下文的答案继承判断。

## 3. 七个根因（按影响排序）

### R1（最高）主回答块裁剪把结果表裁掉了

`evaluator/answer_context.py:20`：

```python
def primary_block(text: str) -> str:
    """Keep the first answer table and its introduction, excluding later comparisons."""
    lines = text.splitlines()
    start = next((i for i, line in enumerate(lines) if line.strip().startswith("|")), None)
    if start is None:
        return re.split(r"\n\s*(?:#{1,6}\s*)?(?:\*\*)?(?:环比|同比|补充|历史对比)", text, maxsplit=1)[0]
    end = start
    while end < len(lines) and lines[end].strip().startswith("|"):
        end += 1
    return "\n".join(lines[:end])      # ← 到此为止，后面全部丢弃
```

这个函数的设计目的是**期间对齐保守化**（不要把环比、同比表里的月份当成主回答月份），逻辑本身没错。问题在于它被复用给了数值抽取。

后果：智能体如果先输出一张「取证过程表」再输出「结果表」——这在实测回答里非常常见——`primary_block` 会**停在过程表末尾**，结果表完全进入不了 `reconcile`。

实测样本：BJ-010 的回答里唯一的表格是「取证过程表」，真正的结论写在表格前后的文字里，`reconcile` 拿到的是过程表；DMA-026 的回答是「先若干段叙述 → 一张多行结果表」，`reconcile` 只拿到叙述段。

**职责必须拆开**：期间对齐继续用 `primary_block`，数值抽取用完整答案。

### R2 容差没有跟答案的显示精度挂钩

`config/contracts.json` 产销差率契约：

```json
"value_scale": "ratio01",
"tolerance": { "kind": "abs", "eps": 0.01, "abs_floor": 0.0 }
```

`evaluator/normalizer.py:105` 会把它 ×100 统一成百分数，于是实际容差是 **±0.01 个百分点**：

```python
if scale == "ratio01":
    if source == "sql" or (abs(value) <= 1 and not unit_word):
        value *= 100
```

`values_close()`（`normalizer.py:150`）按 `abs` 判：

| 智能体答案 | SQL 基准 | 归一后差值 | 判定 |
|---|---|---|---|
| `8.4%` | `8.35%` | 0.05 pp | **MISS（错值）** |
| `8.35%` | `8.35%` | 0 | HIT |
| `8%` | `8.35%` | 0.35 pp | MISS |

智能体四舍五入到一位小数是完全合理的业务表达，却直接构成错值。`_compare_value`（`reconcile.py:221`）还会尝试 ×100 / ÷100 的量级歧义修正，但**不处理精度舍入**。

### R3 比对语义是「整表对齐」，多给一行就降级

`evaluator/reconcile.py:402`：

```python
if row_rate >= 1.0 and not report.get("extra_rows") and (value_rate is None or value_rate >= 1.0):
    return "QUALIFIED"
```

要求「基准行全中 + **答案一行不多** + 数值全中」。

实测后果：

| 案例 | 基准 | 智能体回答 | 现状判定 |
|---|---|---|---|
| JL-012「最低三家」 | 3 行 | 列出全部 18 家单位 | 3 家全对，但 `extra_rows = 15` → 最多 `PARTIAL` |
| DMA-026「各单位…」 | 15 行 | 覆盖 10 个单位 + 集团汇总 | 已给出的数值全对，但 `row_hit_rate = 0.67` → 进不了 `QUALIFIED` |

评测的目标应该是「**基准里的每个值有没有被正确给出**」，而不是「答案表格与基准表格是否同构」。多给信息属于表达差异，不应扣分。

### R4 抽取形态单一

`evaluator/reconcile.py:42` 的 `parse_tables` 只识别 Markdown 表格，且硬性要求：

- 行首必须是 `|`
- 第二行必须匹配分隔线正则 `^\s*\|?[\s:\-|]+\|?\s*$`

因此以下常见形态全部无法抽取：

```
- 环水集团：7.7%
- 南山分公司：12.0%
```
```
单位 | 单月供水量
环水集团 | 1,529,392
```
```
环水集团 2026-06 漏损量 158.37 万 m³，上半年产销差率 5.9%
```

一旦 `available=False`，整题回退给 LLM 判分。而 LLM 判分的典型偏差是「没抽到」→ 记 `MISSING_ROW` / `MISSING_FIELD`，**与真正算错在结论上等价**。

### R5 多表只取一张

`evaluator/reconcile.py:190`：

```python
def _pick_table(tables, measures, contract):
    best = None
    for table in tables:
        ...
        if best is None or score > best[0]:
            best = (score, table, columns, key_columns)
    return best
```

评分规则是 `len(columns) * 10 + (5 if key_columns else 0) + min(len(rows), 20)`，**只奖励列多、行多**。一张多行的过程表很容易压过一张只有几行的结果表，而过程表里的数值是中间量、不是答案。

### R6 维度列定位失败后退回第 0 列

`evaluator/reconcile.py:167`：

```python
if dim not in found:
    # 退回位置约定：第一个维度用第一列
    found[dim] = 0
```

遇到「序号 | 单位 | 指标 | 数值」这类表，第一列是序号，行键全部错位，后续比对彻底失效，且**不报错**——失败被静默吞掉。

### R7 LLM 的否决权没有证据约束

`evaluator/llm_evaluation.py:387`：

```python
if any(code in VETO_CODES for code in evaluation.issue_codes):
    notes.append("程序复核未覆盖语义层判定的期间/粒度/单位/口径问题，保留 LLM 结论")
    return artifact
```

`VETO_CODES = ("PERIOD_MISMATCH", "GRAIN_MISMATCH", "UNIT_MISMATCH", "CALIBER_MISMATCH")`。

LLM 只要误报其中一个，程序算得再准也会被整体推翻，且**不要求提供任何原文证据**。这是结论抖动的另一个高频来源。

## 4. 目标模型：值集合覆盖

### 4.1 核心转变

| | 现状 | 目标 |
|---|---|---|
| 比对对象 | 答案表格 vs 基准表格 | **答案值集合** vs **基准值集合** |
| 对齐方式 | 按行键逐行 | 按 (维度组合, 指标) 匹配 |
| 主指标 | `row_hit_rate`（要求 1.0） | `value_recall` + `coverage` 双指标 |
| 多余内容 | `extra_rows` 直接降级 | `precision` 提示，不进判定 |
| 缺失 | 与错值同义 | `ABSENT` 独立状态 |

### 4.2 形式化定义

```
基准值集合  S = { (k, m, v) }         k=维度组合  m=指标  v=归一化基准值
答案值集合  A = { (k̂, m̂, v̂, span) }   span=答案原文片段

match(s, a) = key_match(s.k, k̂) ∧ (s.m == m̂) ∧ values_close(s.v, v̂, tol(s.v, a))
```

`key_match` 需要处理组织别名、指标别名、期间写法差异（详见 5.3），并输出置信度；置信度低于阈值时该 pair 不参与判定，单独计入 `ambiguous`。

### 4.3 三态与指标

对每个 `s ∈ S`：

| 状态 | 条件 | 含义 |
|---|---|---|
| `HIT` | 存在匹配的 `a` 且数值在容差内 | 正确给出 |
| `MISS` | 存在 (k, m) 相同但数值超容差的 `a` | 给出了错误值 |
| `ABSENT` | 找不到 (k, m) 相同的 `a` | 在答案里定位不到 |

指标：

```
located   = hit + miss
value_recall = hit / located            ← 已定位部分的正确率
coverage     = hit / |S|                ← 基准值被正确覆盖的比例
absent_rate  = absent / |S|             ← 抽取失败率
precision    = |{a : ∃s, match(s,a)}| / |A|   ← 仅作提示
```

**`ABSENT` 不进 `value_recall` 的分母**。这是把「没抽到」和「算错了」分开的关键。

### 4.4 结论分级

| 条件 | 结论 |
|---|---|
| `absent_rate > 0.5` | `UNEVALUABLE`（抽取不足，不是答错） |
| `value_recall == 1.0` 且无硬错 | `QUALIFIED` |
| `value_recall >= 0.8` 且无硬错 | `PARTIAL` |
| `value_recall >= 0.5` 或有硬错 | `PARTIAL` / `UNQUALIFIED` |
| `value_recall < 0.5` 且 `absent_rate <= 0.5` | `UNQUALIFIED` |

「硬错」沿用现有定义：`PERIOD_MISMATCH` / `GRAIN_MISMATCH` / `UNIT_MISMATCH` / `CALIBER_MISMATCH`，但必须满足 5.6 的证据要求。

`precision` 只写入报告，不参与判定；`extra` 内容单独展示，供人工判断「答非所问」。

## 5. 改造设计

### 5.1 抽取层：多形态 + 分级回退

新增 `evaluator/answer_extract.py`，按可靠性依次尝试，前一层产出即停（同时保留各层结果供交叉校验）：

| 级别 | 形态 | 识别特征 | 产出 |
|---|---|---|---|
| L1 | Markdown 表 | 行首 `|` + 分隔线 | (header, rows) |
| L2 | 无边框表 | `a | b | c` 且列数一致 ≥2 行 | (header, rows) |
| L3 | HTML 表 | `<table>` | (header, rows) |
| L4 | 列表项 | `^\s*[-*]\s*名称[:：]\s*数值单位` | (名称, 数值) |
| L5 | 键值行 | `名称[:：\s]+数值` | (名称, 数值) |
| L6 | 段落锚点 | 组织别名命中后 40 字内的首个数值 | (名称, 数值, span) |
| L7 | LLM 定位 | 以上全部为空 | (名称, span) → **verbatim 校验** |

**L7 的关键约束**：LLM 只输出「到哪儿去找」，不输出数值。

```json
{"org": "环水集团", "value_span": "7.7%"}
```

程序拿到 `value_span` 后必须能在原文中精确定位到该子串；定位失败即丢弃。这样 LLM 在结构上不可能改写数字。

> 这一条同时是安全边界：LLM 只做检索，不做转录，避免模型幻觉污染数值。

### 5.2 区域选择：替代粗暴截断

拆开两个用途：

| 用途 | 输入 | 方法 |
|---|---|---|
| 期间对齐 | `primary_block(text)` | 保持现状，保守截断 |
| 数值抽取 | **完整 `agent_answer.text`** | 新增 `answer_regions()` |

`answer_regions()` 把全文切成若干候选区域（按标题、空行分块，或按表格边界切分），每块独立抽取，然后用「契约指标映射命中数」排序取 Top 3，**全部并入值集合**，而不是只选一张。

对 `_pick_table` 的评分也要改：当前只奖励列多行多，应改为

```
score = 命中契约 measure 的列数 × 10
      + 行键列可识别数 × 5
      + min(行数, 20)
      - 含"过程/取证/排查/历史/对比"等标题词的惩罚 10
```

### 5.3 维度对齐：模糊匹配 + 置信度

| 维度 | 归一化 | 置信度 |
|---|---|---|
| 组织 | 查 `organization_aliases.json`；未命中则去括号、去「分公司/水务/公司」后缀再查；仍无则编辑距离 ≤2 匹配 | 完全命中=high，模糊=mid，无=low |
| 指标 | `canonical_metric()` → 表头主干包含 → 别名子串 | 同上 |
| 期间 | `_period_key()` + 题目锚点年份 | 需 `default_year` 确定，否则 low |

**维度列定位失败不再退回第 0 列**，而是标记该列为 `UNRESOLVED`，让该区域整体降置信度；置信度低的值不参与 HIT/MISS 判定，计入 `ambiguous`。

### 5.4 容差自适应

```
effective_tol = max( 契约容差, 半个末位单位(答案显示精度) )
```

| 答案写法 | 推导精度 | 半末位 | 契约容差 | 采用 |
|---|---|---|---|---|
| `8.35%` | 0.01 | 0.005 | 0.01 | 0.01 |
| `8.4%` | 0.1 | 0.05 | 0.01 | **0.05** |
| `8%` | 1 | 0.5 | 0.01 | 0.5 |
| `1,529,392 m³` | 1 | 0.5 | rel 0.001（绝对值 1529） | rel 0.001 |
| `158.37 万 m³` | 0.01 万 | 0.005 万 = 50 m³ | rel 0.001 | rel 0.001 |

注意两条约束：

1. **只能放宽、不能收紧**。`effective_tol = max(契约, 半末位)`，不能因为答案写得多位就把容差压到比契约更严。
2. **单位换算必须在 `normalizer` 里做**，不能另写。当前 `reconcile` 里的 `HEADER_SCALE`（`reconcile.py:24`）和 `normalizer.conversion_meta` 是两套逻辑，应合并到 `normalizer`，避免口径分叉。

### 5.5 结论分级与现有字段的映射

为保持向后兼容，`reconcile` 返回值保留原字段，新增覆盖字段：

| 原字段 | 保持 | 新增 | 说明 |
|---|---|---|---|
| `row_hit_rate` | ✅ | | 仍按原算法算，供历史对比 |
| `value_hit_rate` | ✅ | | 仍按原算法算 |
| — | | `coverage` | 基准值正确覆盖率 |
| — | | `value_recall` | 已定位部分的正确率 |
| — | | `absent_rate` | 定位失败率 |
| — | | `matched` / `wrong` / `absent` | 三态计数 |
| — | | `ambiguous` | 低置信度未判定项 |

`verdict_from_report` 改为优先用新字段；新字段缺失（旧批次）时回退旧逻辑。这样历史批次结论不会因为规则升级而静默改变，重算时能明显看出差异。

### 5.6 仲裁规则：否决权要证据

`apply_reconciliation` 中，LLM 报 VETO 时增加校验：

```python
def veto_has_evidence(evaluation, answer_text) -> bool:
    # VETO 必须在 differences 里给出 coordinate + evidence
    # 且 evidence 必须是 answer_text 的 verbatim 子串
```

- 有证据 → 保留 LLM 结论（并在 `validation_notes` 记录）
- 无证据 → 不否决程序结论，把该码降级为 `WARNING` 写入差异清单，`needs_human_review = True`

### 5.7 题型分派

`result_type` 字段已存在（`stat` / `detail`），但比对逻辑未分派。建议：

| 题型 | 判据 | 比对策略 | 特殊规则 |
|---|---|---|---|
| 标量题 | `result_type=stat` 且基准 1 行 | 全文定位：指标名邻近的数值 | 不做表格解析，避免因无表落空 |
| 清单题 | 基准 N>1 行 | 值集覆盖 | `extra` 不扣分 |
| 极值/排序题 | 题面含「最低/最高/前 N/排名」 | 值集 + 顺序检查 | 顺序错记 `ORDER_MISMATCH` 提示，不直接判不合格 |
| 对比题 | 题面含「哪家更/相比」 | 值集 + 结论方向 | 结论方向错单独记码 |

「最低三家」这类题，多列出其余单位属于补充信息，只要三家在且数值对，应判 `QUALIFIED`。

## 8. 实施计划

### P0：止血（0.5–1 天）

只改两个点，先量化收益：

1. **R1**：`reconcile` 改用完整 `agent_answer.text`，`primary_block` 只服务期间对齐。
2. **R2**：容差按答案末位自适应。

**验收**：对校准集重算，统计误判率下降幅度。预期这一步能消掉一半以上的误判。

### P1：抽取多形态（2–3 天）

3. 新增 `evaluator/answer_extract.py`，实现 L1–L5。
4. `_pick_tables` 替代 `_pick_table`，Top 3 合并。
5. 维度列定位失败不退回第 0 列，标记 `UNRESOLVED`。

**验收**：`extract_coverage` 从当前水平提升到 ≥ 90%（校准集）。

### P2：值集合语义（2–3 天）

6. 三态判定 `HIT` / `MISS` / `ABSENT`。
7. 双指标 `coverage` / `value_recall` + 新分级表。
8. `extra` 降级为提示。

**验收**：JL-012、DMA-026 这类「数据对但判错」的题型，重算后结论与人工一致。

### P3：仲裁与兜底（1–2 天）

9. VETO 证据校验。
10. L7 LLM 定位 + verbatim 校验。
11. 题型分派。
12. 详情页渲染 `items`。

**验收**：LLM 误报 VETO 不再推翻正确结论；无表格答案的抽取覆盖率达到 L1–L5 的水平。

### P4：校准与固化（持续）

13. 建校准集（见附录 B）。
14. 回归脚本接入 `pytest`，规则改动必须跑通。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 容差放宽过度 | 真错值被放过 | 只放宽到「半个末位」，且设 `max_tolerance_relax_factor` 上限；越界需在报告中标注 |
| 值集合匹配误配 | 把 A 单位的数值配到 B 单位 | 维度置信度门槛；`ambiguous` 不判定；报告中保留 `answer_span` 供人工核对 |
| 多表合并引入干扰值 | 过程表里的中间值被当成答案 | 区域评分含标题惩罚；同一 (k,m) 出现多个候选值时取「结果区优先」，冲突记 `AMBIGUOUS_VALUE` |
| 抽取器误识别 | 把日期、编码当成数值 | 复用 `normalizer.is_non_metric_entity()`（已处理日期、编号、排名） |
| 指标口径分叉 | `reconcile` 与 `normalizer` 两套单位换算 | 强制合并到 `normalizer`，删除 `HEADER_SCALE` |
| 历史批次不可比 | 结论波动 | v1/v2 并存；重算走离线命令，不自动覆盖 |

## 10. 验收与量化

### 10.1 校准指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 误判率 | 人工判对但系统判错的题数 / 人工判对的题数 | < 5% |
| 漏判率 | 人工判错但系统判对的题数 / 人工判错的题数 | < 10% |
| 抽取覆盖率 | 至少抽到 1 个基准值的题数 / 总题数 | ≥ 95% |
| 可解释率 | 判定项含 `answer_span` 的比例 | = 100% |

### 10.2 必测样本

必须包含以下形态，且人工结论已知：

1. 单值标量题，答案只写一句话。
2. 清单题，答案给的表比基准多行（JL-012）。
3. 清单题，答案给的表比基准少行（DMA-026）。
4. 答案为无序列表（`- 单位：值`）。
5. 答案为无首尾竖线的表格。
6. 答案先输出过程表、后输出结果表（R1 专项）。
7. 数值四舍五入到 1 位小数（R2 专项）。
8. 单位写成「万 m³」而基准是 m³。
9. 百分比写成小数（0.0835 vs 8.35%）。
10. 答案含多个年份/期间的同类数值，需只取主期间。

## 附录 A：典型误判复盘

### A1. JL-012「最低三家」

- 基准：3 行（最低三家）
- 答案：18 家单位的完整排序表，前 3 家与基准完全一致
- 现状：`extra_rows = 15` → 最多 `PARTIAL`
- 正确结论：`QUALIFIED`（多列信息属于加分，不是错误）
- 涉及根因：R3

### A2. DMA-026「各单位 DMA 漏损量」

- 基准：15 行
- 答案：只覆盖其中一部分单位（实测截断前可见 7 行）+ 集团汇总，已给出的数值全部正确
- 现状：`row_hit_rate` 明显低于 1.0 → 进不了 `QUALIFIED`
- 正确结论：取决于「是否要求全单位」——若题目要求"各单位"，缺行应判 `PARTIAL`；若这些单位确实无数据，应判 `QUALIFIED`
- 涉及根因：R1（过程表裁剪）、R3（extra/missing 语义）

### A3. 四舍五入

- 基准 `8.35%`，答案 `8.4%`
- 现状：`MISS`（差值 0.05 pp > 容差 0.01 pp）
- 正确结论：`HIT`（在答案精度范围内）
- 涉及根因：R2

### A4. 列表格式

- 答案：`- 环水集团：7.7%` 共 12 行
- 现状：`parse_tables` 返回空 → `available=False` → 全交 LLM
- 正确结论：应正常抽取并比对
- 涉及根因：R4

## 附录 B：校准集建设

### B1. 规模与构成

- 20–30 题，覆盖 5 个场景大类
- 每题必须有：人工结论（合格/部分/不合格）、基准值、判定理由
- 优先收录历史上被人工平反过的题（这些是已知的误判样本）

### B2. 记录格式

```json
{
  "case_id": "JL-012",
  "run_id": "20261103_225332_4d06",
  "human_verdict": "QUALIFIED",
  "human_reason": "三家数值与基准完全一致，多列其余单位属于补充信息",
  "expected_values": [{"key": "龙华水务公司", "measure": "检漏效率", "value": 0.0007}],
  "known_traps": ["extra_rows_penalty", "process_table_first"]
}
```

### B3. 回归脚本

```
python -m evaluator.recompare --calibration docs/calibration_set.json --report
```

输出：每题「系统结论 vs 人工结论」、误判率、抽取覆盖率、逐项状态分布。任何规则改动前后跑一次，数字必须可比。
