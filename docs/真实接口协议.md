## 2. 连通测试结果

使用用户提供的组织、记录ID和凭证，对上述指定地址发起POST；凭证仅用于请求，未写入本文件和配置文件。

再次读取同一指定任务确认短响应正文：

```json
{"data":{"taskList":[],"isFinish":true},"respCode":"SUCCESS"}
```

结论：

- 网络和HTTP层能够到达该接口，服务返回业务码SUCCESS。
- 本次taskList为空，没有拿到用户附件里的执行记录。
- 空列表加isFinish=true不能证明指定任务确实被取回，也不能据此判定问答生成成功。
- 尚不能区分记录ID含义/查询时机/接口是否返回增量、数据已迁移，或访问身份范围等原因；没有证据判定凭证一定有效或已经过期。
- 不枚举其他组织/任务ID。下一次应以浏览器现场同一请求、同一时刻的返回为对照。

### 8.2 返回事件

HTTP 200，Content-Type为 `text/event-stream`。SSE的 `data:` 内容为JSON，事件类型在JSON的type字段，不依赖SSE的event行。

捕获98个事件帧，观察到：

| type | 用途 |
|---|---|
| response.pending | 进入排队；本次明确提示“当前会话有任务正在执行” |
| response.queue.update | 队列位置变化 |
| heartbeat | 心跳，有timestamp，不是答案片段 |
| response.created | 创建生成响应，response含id、created_at、status=in_progress |
| response.output_item.added | 输出项开始，需检查item类型 |
| response.content_part.added | 内容片段开始 |
| response.function_call_arguments.delta/done | 工具调用参数，不能当用户答案 |
| response.output_item.done | 某个输出项结束；本次观察到工具调用项结束，不能当整轮完成 |
| response.output_text.delta | 可见答案增量，按item_id、output_index、content_index归属后拼接 |

### 8.4 耗时与超时

- 本次开始墙钟：2026-09-07T08:02:49.099827+00:00，即北京时间16:02:49左右。
- 响应Header约354.6毫秒；首个body数据约354.8毫秒，对应排队消息，不是首答。
- 外部捕获结束约84.57秒，包含队列等待、生成和最后30秒读取空闲等待。
