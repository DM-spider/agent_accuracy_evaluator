# 真实智能体测评接入说明

更新日期：2026-09-07。

## 已实现

- 平台 SSE POST 接入，会话与 Cookie 仅从 settings.toml 中的 Bash cURL 提取，不再使用逐字段配置或登录环境变量。
- 同一 sessionId，默认 CX01 至 CX10 顺序执行；每轮完整结束后才发下一题，不附带 SQL、SQL 结果或标准答案。
- 使用实际回答主表中的明确年月绑定独立黄金 SQL。原业务 SQL、组织集合和计算公式不修改。
- 每题保存原始回答正文、脱敏请求信息、事件类型及接收时刻、SQL 快照、绑定参数、逐指标差异、对齐原因。
- 首段回答、完整响应、传输总耗时分别计时；SQL 总耗时包含连接、执行和结果读取，不含 Agent 等待。
- 首页查看历史批次；批次页查看准确率、待复核数、平均耗时；详情页查看逐项差异、期间与口径、请求响应、日志。
- JSON/Excel/离线 HTML 导出包含期间与复核证据。离线 HTML 展开题目即可复核，不会访问数据库或智能体。

## 本地配置

本机 `config/settings.toml` 已填入用户提供的会话、任务、模板与组织标识，并通过 `database.env_file` 引用项目已有 `backend/config/.db.env`，不复制密码。

本机私有配置、runtime、构建输出均不提交 Git，也不打进分发包。给同事使用时，应配置他们自己的会话和登录凭证，不能沿用本机共享会话。

更换会话时，在业务网页发送一条消息，F12 中找到 message/stream 请求，选择 Copy as cURL (bash)，将整段内容替换到 `config/settings.toml` 的 `[platform]` 下：

```toml
[platform]
enabled = true
curl = '''
在这里粘贴完整的 curl 命令
'''
```

三单引号内直接粘贴，无需修改 Bash 的单引号或续行反斜杠。仅解析请求，不执行命令；请求中的 message 自动由测评题目替换。配置含 Cookie，请勿提交或分发。粘贴后重启服务；当前正在执行的批次先等待结束。

启动命令：

```powershell
python start.py
```

也可以从命令行运行，走与页面相同的预检、持久化和核验流程：

```powershell
python run_live.py --cases CX01
python run_live.py
```

第二条命令默认十题。网页选择“实时调用智能体与数据库”和“同一会话顺序 10 题”。当前最多十题；执行时不要在业务网页对同一会话继续发问。

`platform.trust_env=false` 默认不使用系统代理，TLS 证书校验保持开启。本机实测代理会导致 WinError 10053，直连业务域名正常。需要企业代理的同事可以按其网络配置调整该选项。

缺少数据库凭证或数据库预检失败时，不发送问题，也不会拿历史 expected 冒充实时 SQL 结果。

真实批次锚点强制取当前时间，不支持通过页面输入历史时间模拟远端智能体时钟。历史时间回放仅用于 Mock 模式。接入原普通 JSON 接口时，显式设置 `platform.enabled=false`。

## 完整回答与暂停

- 已实测的成功终态：`response.completed`，并且 `response.status=completed`。
- `response.output_item.done` 可能只是工具调用完成；心跳、EOF、HTTP 200、`[DONE]` 单独出现都不是本适配器认可的完整回答。
- 断流、空闲超时、未知事件结构等保留部分正文，本轮不评分，停止后续题目；不自动重发 POST。
- 不确定远端状态时保留磁盘会话锁，重启程序也不会自动重复提交。
- 本机前置建连失败明确属于未发送，仍暂停该批次，但不会保留不必要的远端状态锁。
- “确认网页任务已结束，解除暂停”是人工确认入口，不会取消远端任务。只有确认网页已空闲后才能操作。
- 当前没有已验证的历史恢复/轮询接口，也没有自动续接半条回答。

## 时间与口径判定

本次先完成可审计的保守版本，不宣称 73 题已经全部支持自动对齐：

1. 自动识别主回答首张表及其前导文字中的唯一、明确年月，避免后面环比、同比、年累计表污染主值。
2. 当前自动绑定范围是单个业务年月，以及同一年的 `year_start`。缺年月、多个年月、复杂日期边界、近 N 月序列等均进入 REVIEW，不能可靠绑定时不执行 SQL。
3. 单月/年累计冲突，或者组织范围不明确，保留问题，不把它们消除后再声称数值正确。
4. 回答从“本月”回退到上月时，可以按回答月份查 SQL；同时保留 `PERIOD_FALLBACK_REVIEW`，因为数值一致不能证明“最新完整月”判断正确。
5. REVIEW 不计入首页/概览的数值准确率和题目通过率。详情中的 `conditional_numeric_status` 只表示所选期间、原黄金 SQL 下的条件比较，不是最终业务结论。
6. 原黄金契约中没有覆盖的指标、缺列、截断结果、重复坐标都不能当成验证通过。当前范围是主回答和契约声明的指标，并非完整自然语言事实核验。
7. 相同月份不等于同一数据库事务快照。前后水位检测只是辅助证据，无法证明跨系统底层数据完全同步；未变化不能替代数据版本证明。

后续应逐题补齐复杂日期边界、组织集合和最新完整期规则的结构化契约，再逐步提高自动评分覆盖率。不要让 Agent 自己的 SQL 成为核验它的唯一依据。

对现有 55 道数值契约的驱动参数绑定预检中，54 道通过绑定检查（不代表业务 SQL 已执行正确）；RS06 仍缺少 `year_start_ym` 参数，且原模板包含多段独立 SELECT，需拆分为有明确返回字段的子查询契约。该题本版会进入复杂期间复核，不会宣称自动验证通过。

## 真实冒烟结果

单题冒烟批次：`20260907_165318_e5d2`。之后又发起了同会话十题批次，详见下一节。

问题：集团本月产销差率是多少？供水量、售水量各多少？

- 请求锚点：2026-09-07 16:53:18（北京时间）。
- 回答月份：2026 年 8 月，声明 9 月暂无数据。
- 完整回答：已收到 `response.completed`。
- 首段回答：110.08 秒；完整响应：114.32 秒；SQL 查询：0.315 秒。
- SQL 已绑定 `period=202608`，前后水位一致。

| 指标 | Agent 回答（归一化） | 原黄金 SQL（202608） |
| --- | ---: | ---: |
| 供水量 m³ | 51,661,000 | 157,439,172.49 |
| 售水量 m³ | 44,517,100 | 144,412,263.00 |
| 产销差率 % | 13.83 | 8.27 |

原黄金 SQL 保留指定 12 家单位的 zoneid 集合。额外只读诊断查得 F100 的 202608 记录为供水量 51,661,039.10、售水量 44,517,146、产销差率 13.83%，与 Agent 展示到 0.01 万 m³ 的结果一致。

这支持“Agent 返回集团本部范围，而黄金 SQL 是指定单位汇总”的判断；尚不能证明 Agent 内部究竟执行了哪条 SQL，也不能据此认定底表错误。组织口径需要业务确认，未修改黄金 SQL 来迎合回答。

诊断 SQL（不是替换后的黄金 SQL）：

```sql
SELECT zoneid, businessyearmonth, totalproduct, totalconsume,
       ROUND((totalproduct-totalconsume)*100.0/NULLIF(totalproduct,0),2) AS rate
FROM dwd_lsxt_fqcxfx
WHERE zoneid IN ('F100','F1')
  AND periodtype='SzwgBusiness'
  AND businessyearmonth IN (202608,202609)
ORDER BY businessyearmonth, zoneid;
```

# SQL 结果缺失修复

期间无法自动对齐时，不再提前跳过数据库查询，而是按原请求参数执行参考查询，保持 REVIEW 且不评分。详情页区分未执行、SQL 错误及成功返回零行。

历史批次可在题目详情的“SQL 与参数”中使用“仅查询 SQL”，修改 JSON 参数后执行原批次保存的 SQL 模板，不向智能体发送新消息。补查只追加证据，记录真实补查时间，不覆盖原快照、回答或准确率。补查结果与原测评并非同一时刻，不能作为当时数据库状态的证明。JSON、HTML、Excel 导出均包含补查记录。
