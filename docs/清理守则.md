# 清理守则 —— 功能删除/重构后不留痕迹

> 用途：每次删除功能、字段、接口或调整口径后，按本文自查；也可整段作为提示词交给编码助手执行。
> 执行前明确两件事：① 清理范围（仓库/目录）；② 本轮涉及的功能、字段或旧标识。

## 一、原则

只描述**当前真实状态**。删掉的东西就是不存在，不存在的东西不该出现在任何位置：代码、注释、文档、配置注释、数据口径、测试名、文件名。

| 场景 | 错误做法 | 正确做法 |
|---|---|---|
| 删除某列 | 文档写"（无某某列）" | 文档不提及这件事 |
| 删除某个模式 | 保留"某某已移除"字样或旧标识 | 全仓不再出现该功能字样 |
| 更换旧口径 | 写"（不含旧口径）""（已回归新定义）" | 直接写新口径 |

## 二、必须清理的模式

1. **负向说明**：无X、不含X、没有X、不支持X、不引用X、不做X、不用X、无版本号、X 为空/未启用
2. **历史叙述**：曾、原、旧、老、历史、此前、不再、已删除/已移除/已废弃、废弃、回归、修正版、迁移、兼容旧、遗留
3. **变更日志式注释**：`日期：改为…`、`修复…`、`重构…`、`原逻辑…` —— 代码与正式文档不写 changelog，历史只归 git 提交信息
4. **已删功能的残留标识**：变量/函数/参数/字段/数据库列/文件名/目录名/接口路径/前端文案/测试名/注释/README/docs/配置注释/提示词/生成脚本/生成产物（契约、JSON、Excel、MD 中的口径与字段）
5. **双重表述与版本命名**：`X（已废弃）`、`legacy` / `old` / `v1` / `new` 式命名
6. **空占位列/字段**：字段还在但永远为空，或只为展示"无内容"而存在，应删除并同步生成器

## 三、允许保留否定的唯一四种情况

保留必须写明理由，其余一律不留：

- 运行时用户可见的报错/提示，语义上必须说明"不接受什么"（如"实时批次不接受历史时间"）
- 业务/技术硬性规则（如"比率禁止 ×100""期间一律 create_time 半开区间"）—— 这是现行规则，不是历史
- 可执行护栏：防回归断言里可以出现被禁标识符（如 `assert "旧字段" not in sql`），但注释不得再讲历史
- 面向使用者的现行能力边界（帮助文档里的"本接口不支持分页"），前提是它描述当前事实且对使用者有用

## 四、执行流程

1. 列出本轮删除/优化涉及的名称与标识符（从 git diff/log、提交信息、需求描述中提取）。
2. 全仓扫描：

   ```bash
   # 旧标识符
   grep -rn "<功能名>\|<字段名>\|<旧标识>" .
   # 负向/历史句式
   grep -rn "不再\|已删除\|已移除\|已废弃\|无.\{0,6\}\(列\|字段\|模式\|版本\)\|不含\|曾\|历史\|遗留\|legacy\|deprecated\|回归\|迁移\|旧" \
     --include="*.py" --include="*.md" --include="*.js" --include="*.html" --include="*.cjs" --include="*.toml" --include="*.json" .
   # 文件名/目录名
   find . -iname "*<旧标识>*"
   ```

3. 逐条判定：**删除** / **改写为正面描述** / **保留（命中例外并写明理由）**。
4. 生成物（契约、JSON、Excel、MD）先改生成器，再重建或回填，保证生成器与产物一致；同步更新测试断言。
5. 改完重扫：已删功能的命中数必须为 0（仅例外清单可保留）。
6. 验证：静态检查 + 测试 + 生成物抽查（数量、字段、关键文案）。
7. 汇报格式：

   | 位置 | 原文 | 处理 | 理由 |
   |---|---|---|---|

   末尾附最终 grep 结果（应为空）与例外清单。

## 五、硬性要求

- 不写"X（已删除）"式标注；不做"无 X 版"命名；不留注释形式的历史。
- 一次改干净，不留 TODO 或"后续再清理"。
- 发现某功能其实仍在使用时，先停下向用户确认，不擅自清理。
- 大范围改动后跑一遍测试与渲染/构建，确认行为不变。

## 六、常见漏点清单

- [ ] 代码注释与 docstring
- [ ] README、docs/、使用说明、接入说明
- [ ] 配置注释（settings.toml / settings.example.toml）
- [ ] 前端文案（按钮、表头、空态、提示）
- [ ] 测试文件名、用例名、断言注释
- [ ] 生成器与生成产物（两份必须一致）
- [ ] 文件名与目录名
- [ ] 防回归断言（保留断言、清理历史解释）
