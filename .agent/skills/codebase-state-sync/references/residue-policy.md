# 代码库当前状态同步规则

## 核心原则

删除、替换、改名或调整后的概念只存在于版本历史中。正式源码、注释、文档、配置、测试、界面和生成物只描述当前有效状态。

不要写：

- “无某字段”“不含某列”“不再支持某模式”
- “旧版”“历史逻辑”“原实现”“已删除”“已废弃”“迁移后”
- 日期式或提交日志式注释，例如“2026-xx-xx 改为……”
- `legacy`、`old`、`new`、`v1` 等仅用于区分变更前后的临时命名
- 永远为空、只用于展示“没有内容”的字段或列

直接描述当前存在的结构、能力和业务规则。

## 允许保留的否定表达

只有以下现行语义可以保留：

1. 运行时必须向用户说明的输入限制或错误提示。
2. 当前业务或技术硬性规则，例如禁止某种换算。
3. 防回归断言中对禁用标识符的检查；注释不得继续讲述历史。
4. 使用者必须知道的当前能力边界。

保留项必须能说明其当前用途；“帮助以后理解历史”不是保留理由。

## 概念集

每次执行都根据本轮变化建立概念集，不使用固定的全仓禁词表。概念集至少考虑：

- 精确标识符及大小写、单复数、连字符和下划线变体
- 中文业务名称、缩写、别名和界面显示名称
- 函数、类、参数、字段、数据库列和序列化键
- API 路径、错误码、配置键和环境变量
- 文件名、目录名、测试名、Fixture 与快照键
- 版本式名称和临时兼容别名

历史词只能作为发现候选项的信号，不能在没有上下文时机械删除。

## 扫描范围

根据仓库技术栈检查适用位置：

- 源码、注释、docstring、类型定义和公共导出
- README、docs、接入说明和示例
- 配置文件、配置样例和部署文件
- 前端按钮、表头、空态、提示和无障碍文本
- 测试文件、测试名、断言、Fixture、快照和 Mock
- SQL、数据库映射、序列化模型和接口契约
- 提示词、模板、生成脚本和生成产物
- 文件名、目录名、路由和静态资源引用

搜索时优先使用 `rg` 和 `rg --files`；排除 `.git`、依赖缓存、构建缓存和其他明确不属于源码事实的目录。

## 处理规则

对每个命中项选择一种处理：

- **删除**：内容或入口已失效，且无当前消费者。
- **同步**：仍需表达当前能力，但名称、结构或口径需要更新。
- **正向改写**：去掉历史对比，直接陈述当前事实。
- **保留例外**：符合允许保留的现行否定表达，并记录具体理由。
- **停止确认**：代码表明旧概念可能仍被真实功能、外部接口、配置驱动路径或生成流程使用。

不要留下 TODO、“稍后清理”或兼容占位。不要用无意义的新名字掩盖旧结构。

## 生成物同步

命中契约、JSON、Excel、Markdown、代码生成文件或快照时：

1. 找到拥有该内容的生成器或数据源。
2. 优先修改生成器或源数据。
3. 使用项目既有方式重新生成。
4. 核对生成器与产物的数量、字段、命名和关键文案。

只有在仓库明确将产物作为人工维护文件时，才直接编辑产物。

## 验证与报告

修改后使用同一概念集重新扫描。报告应简洁列出：

| 位置 | 处理 | 当前结果 |
|---|---|---|
| 文件或模块 | 删除 / 同步 / 正向改写 | 当前状态说明 |

末尾必须包含：

- 旧概念最终扫描结果
- 保留例外及其现行理由
- 已执行的测试、构建、渲染或生成物检查
- 因仍在使用而未处理的项目
