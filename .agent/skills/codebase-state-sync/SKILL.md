# Codebase State Sync

## 目标

在已获授权的功能变更完成后执行全仓收尾，使源码、配置、文档、测试、界面和生成物对当前状态保持一致。不要把正式内容写成变更日志，也不要用否定旧状态的方式描述当前实现。

## 触发与边界

- 当用户删除、替换、改名或调整功能、字段、接口、配置、业务术语或数据口径时，可随该修改隐式触发。
- 当用户明确要求“清理干净”“全仓同步”“不留旧表达”时触发。
- 用户只要求检查或报告时，只审计，不修改。隐式触发不得扩大原请求的修改范围或外部操作权限。
- 不主动发现或删除既有死代码，不做性能优化、架构重写、代码异味治理或无关格式调整。

开始工作前必须完整阅读 [references/residue-policy.md](references/residue-policy.md)。

## 工作流

1. 从用户请求、当前改动和相关命名中建立本轮“变更概念集”：旧标识符、业务词、显示文案、配置键、接口路径、文件名及常见变体。
2. 扫描所有可能承载这些概念的位置，包括源码、注释、文档、配置、测试、前端、SQL、数据库映射、提示词、文件路径、生成器与生成物。
3. 逐条判断并直接处理已授权范围内的残留：删除失效内容、改写为当前正向表述、同步调用方，并先修改生成器再重建产物。
4. 如果命中项仍被真实功能使用，停止处理该项并向用户说明；不要为了命中归零而破坏现行行为。
5. 修改后重新扫描变更概念集。除规则允许的现行例外外，失效标识和历史叙述命中数应为零。
6. 运行与风险相称的静态检查、测试、构建或渲染，并抽查生成物的数量、字段和关键文案。

## 完成标准

- 仓库各层只描述当前真实状态。
- 生成器、生成物、契约和测试保持一致。
- 未留下空字段、空列、失效入口、历史式注释或以旧概念命名的文件。
- 最终报告列出实际修改、验证结果、最终扫描结果，以及仍保留的例外及其现行理由。
